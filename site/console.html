Pour le parc

Console centrale SpokaPilote Server

Chaque poste envoie le rapport de ses analyses et de ses installations ; l'équipe informatique voit d'un coup d'œil les postes à traiter et le matériel qui n'a pas encore de pilote, sur tout le parc. La console est auto-hébergée : un seul conteneur Docker, aucune base de données externe, aucun service tiers.

Ce que vous suivez

Vue d'ensemble

Postes sains et à traiter, postes non vus depuis 7 jours, matériel sans pilote, pannes matérielles, pilotes bloqués par la politique, échecs d'installation.

Fiche de chaque poste

Système, périphériques en erreur, pilotes proposés ou bloqués, résultats d'installation, historique des derniers rapports, rapport complet téléchargeable.

Matériel sans pilote

Regroupé par identifiant matériel sur tout le parc, avec les postes et modèles concernés ; export CSV.

Politique et imprimantes

La politique de pilotes et le profil d'imprimantes se modifient en ligne ; les postes les récupèrent automatiquement avec leur jeton.

Actions à distance

Depuis la fiche d'un poste ou une sélection : analyser, installer les pilotes manquants ou les mises à jour, déployer les imprimantes, annuler la dernière intervention, mettre à jour SpokaPilote. L'agent du poste exécute l'action et renvoie le résultat.

Note de santé

Chaque poste reçoit une note de A à E ; le parc se trie par note, et les pilotes dangereux déjà installés sont signalés en priorité.

Alertes

E-mail (SMTP), Microsoft Teams, Discord, Slack ou webhook générique : poste devenu critique, pilote dangereux, échec d'installation, poste silencieux. Une seule alerte par sujet et par 24 heures.

Comptes et rôles

Un compte par technicien : Administrateur, Technicien ou Lecture seule. Mots de passe protégés, sessions sécurisées, et un journal d'audit de qui a fait quoi, exportable.

Groupes et planification

Groupes de postes par site, modèle ou sous-réseau, remplis automatiquement ; actions planifiées par groupe (ex. pilotes manquants chaque lundi à 12 h 30), dans une fenêtre de maintenance.

Installation en deux commandes

Sur un serveur Linux ou Windows avec Docker :

docker run -d --name spokapilote-server --restart unless-stopped \
  -p 8080:8080 -v spokapilote-data:/data \
  ghcr.io/spokator/spokapilote-server:latest
docker logs spokapilote-server   # jetons générés au premier démarrage

En production, placez la console derrière un reverse proxy HTTPS (Caddy, nginx, IIS) : exemples prêts à l'emploi dans le guide.

Enrôler les postes

Sur chaque poste (ou une fois pour tout le parc via le fichier de configuration déployé par GPO / Intune) :

spokapilote config set ServerUrl https://spokapilote.exemple.fr
spokapilote config set ServerToken <jeton-d-enrolement>
spokapilote server status

Les rapports partent ensuite automatiquement après chaque analyse ou installation, y compris depuis la maintenance planifiée.

Conçue pour être sûre

  • Deux jetons distincts : administrateur (console, API d'administration) et enrôlement (les postes ne peuvent qu'envoyer leurs rapports et lire la politique) ; comparaison en temps constant.
  • Conteneur durci : utilisateur non root, système de fichiers en lecture seule, sonde de santé, données isolées dans un volume.
  • Vos données restent chez vous : base SQLite locale, aucune télémétrie, aucun service externe.
  • Taille des rapports limitée et historique borné par poste (réglables).
  • Actions à distance sur liste blanche : la console ne peut demander que des actions SpokaPilote prédéfinies, jamais une commande arbitraire.
  • Protection contre les essais de jetons : blocage temporaire après des échecs répétés, et profil HTTPS automatique (Caddy) dans le fichier Docker Compose.
